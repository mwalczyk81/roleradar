# ADR 0017: Single-Owner Credential Handling and Authentication Security Controls

- **Status**: Accepted
- **Date**: 2026-10-25
- **Feature**: `005a-api-and-login`

## Context and Problem Statement

RoleRadar is a single-owner application holding personal job-search data and strategic career assessments. While the portfolio repository is public, access to the application via HTTP APIs and the future web UI must be protected with defense-in-depth authentication.

Key requirements from the specification include:

1. Single owner authentication via strong password and Time-Based One-Time Password (TOTP) second factor.
2. CLI-driven owner account provisioning (`roleradar identity create-owner`) that displays the TOTP secret and QR code once interactively, without persisting secrets or credentials to config files, repository files, or logs.
3. Brute-force protection: 15-minute lockout after 5 consecutive failed login attempts.
4. Endpoint rate limiting to protect login and token endpoints from automated flooding.
5. Strict token lifetimes: 10-minute access tokens, 30-day rotating refresh tokens with reuse detection, 5-minute client credentials tokens, and 60-second authorization codes.

How should user management, second-factor setup, lockout, and rate limiting be configured and implemented?

## Decision Drivers

- **Zero Credentials in Repository or Logs (Constitution Principle I)**: No seed passwords, pre-shared secrets, or TOTP keys in files.
- **Defense in Depth**: Password + TOTP 2FA, short-lived tokens, rotating refresh tokens with reuse detection, and IP-based rate limiting.
- **Framework Native Facilities**: Utilize battle-tested ASP.NET Core Identity and ASP.NET Core 10 Rate Limiting rather than custom cryptographic security logic.

## Decision Outcome

Chosen design: **ASP.NET Core Identity + SQLite User Store + Built-in ASP.NET Core 10 Rate Limiting + CLI Interactive Setup**.

### 1. User Store and 2FA Configuration

The owner account is represented by `IdentityUser<Guid>` stored in the SQLite operational database (`IdentityAppDbContext`) using `Microsoft.AspNetCore.Identity.EntityFrameworkCore` version `10.0.14`.

- **Password Hashing**: Framework default PBKDF2 with HMAC-SHA512 / 100,000+ iterations.
- **Second Factor (TOTP)**: Standard RFC 6238 authenticator app via `UserManager.GetAuthenticatorKeyAsync` and `UserManager.ResetAuthenticatorKeyAsync`.
- **Lockout Policy**:

  ```csharp
  options.Lockout.AllowedForNewUsers = true;
  options.Lockout.MaxFailedAccessAttempts = 5;
  options.Lockout.DefaultLockoutTimeSpan = TimeSpan.FromMinutes(15);
  ```

### 2. Interactive CLI Provisioning (`roleradar identity create-owner`)

The owner account is created through the CLI host:

1. Command verifies that no owner account currently exists in the identity database (refuses to run if already initialized).
2. Interactively prompts for username and reads password from terminal without echoing characters to screen (`Console.ReadKey(intercept: true)`).
3. Creates the `IdentityUser<Guid>` with normalized email/username.
4. Generates a new authenticator key using `UserManager.ResetAuthenticatorKeyAsync`.
5. Formats the `otpauth://totp/RoleRadar:{username}?secret={key}&issuer=RoleRadar` URI.
6. Renders an ASCII text QR code directly to the terminal console along with the raw Base32 secret string.
7. Prompts the owner to enter the 6-digit TOTP code generated by their authenticator app to verify successful configuration before activating the account.
8. Writes zero secret data to disk or logs.

### 3. Rate Limiting Configuration

Using ASP.NET Core 10 built-in rate limiting (`Microsoft.AspNetCore.RateLimiting`):

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;

    // Auth endpoints: 10 requests per minute per remote IP
    options.AddPolicy("auth-rate-limit", httpContext =>
        RateLimitPartition.GetFixedWindowLimiter(
            partitionKey: httpContext.Connection.RemoteIpAddress?.ToString() ?? "unknown",
            factory: _ => new FixedWindowRateLimiterOptions
            {
                PermitLimit = 10,
                Window = TimeSpan.FromMinutes(1),
                QueueLimit = 0
            }));
});
```

Applied to `/Account/Login` and `/connect/token`.

### 4. Token Lifetimes & Rotation Policy

Configured in Duende IdentityServer:

```csharp
new Client
{
    ClientId = "roleradar-web",
    ClientName = "RoleRadar Web Application",
    AllowedGrantTypes = GrantTypes.Code,
    RequirePkce = true,
    RequireClientSecret = true,
    ClientSecrets = { new Secret(builder.Configuration["Clients:Web:Secret"]!.Sha256()) },
    RedirectUris = { builder.Configuration["Clients:Web:RedirectUri"]! },
    PostLogoutRedirectUris = { builder.Configuration["Clients:Web:PostLogoutRedirectUri"]! },
    AllowedScopes = { "openid", "profile", "roleradar.api", "offline_access" },

    // Lifetimes
    AccessTokenLifetime = 600,             // 10 minutes
    AuthorizationCodeLifetime = 60,         // 60 seconds
    AbsoluteRefreshTokenLifetime = 2592000, // 30 days
    SlidingRefreshTokenLifetime = 1296000,  // 15 days
    RefreshTokenUsage = TokenUsage.OneTimeOnly,
    RefreshTokenExpiration = TokenExpiration.Sliding,
    UpdateAccessTokenClaimsOnRefresh = true
},
new Client
{
    ClientId = "roleradar-headless",
    ClientName = "Headless Automation Client",
    AllowedGrantTypes = GrantTypes.ClientCredentials,
    ClientSecrets = { new Secret(builder.Configuration["Clients:Headless:Secret"]!.Sha256()) },
    AllowedScopes = { "roleradar.api.read" },
    AccessTokenLifetime = 300              // 5 minutes
}
```

## Consequences

- **Good**: Zero hardcoded credentials or seeds; interactive TOTP enrollment ensures verified 2FA setup.
- **Good**: Rate limiting and lockout prevent brute-force attacks against the single owner account.
- **Good**: Short 10-minute access tokens and rotating refresh tokens with reuse detection enforce continuous zero-trust security.
