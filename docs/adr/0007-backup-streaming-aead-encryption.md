# ADR 0007: Streamed Backup Authenticated Encryption (`Geralt` libsodium `secretstream` + `Argon2id`) and Two-Pass Restore

- **Status**: Accepted
- **Date**: 2026-10-17
- **Feature**: `001-memory-replacement`

## Context and Problem Statement

RoleRadar backups stream `mongodump --archive --gzip` directly into an encrypted `.rrbak` file (`FR-014`, `FR-015`, `SC-006`, Constitution Principles I and VII). Because no plaintext temporary file may ever be written to disk, encryption and decryption must operate over arbitrary-length streams in fixed-size chunks. Furthermore, authenticated encryption is mandatory: wrong passphrases, bit flips, truncated streams, dropped chunks, and reordered chunks must all be cryptographically detected before any data is restored into MongoDB.

We evaluated maintained .NET bindings for libsodium (`crypto_secretstream_xchacha20poly1305` + `Argon2id`) on NuGet.org on 2026-10-17 against a fallback hand-rolled chunked `AES-256-GCM` + `PBKDF2-SHA256` construction.

## Decision Outcome

Chosen option: **Use `Geralt` `4.4.0` (`Geralt.IncrementalXChaCha20Poly1305` + `Geralt.Argon2id`) with a Two-Pass Restore protocol**.

### 1. Binary `.rrbak` Archive Format (`v1`)

| Offset | Size (Bytes) | Field | Description |
|--------|--------------|-------|-------------|
| `0..3` | `4` | `Magic` | ASCII `"RRBK"` (`0x52, 0x52, 0x42, 0x4B`) |
| `4` | `1` | `FormatVersion` | `0x01` |
| `5` | `1` | `Flags` | `0x00` (reserved) |
| `6..9` | `4` | `Argon2Iterations` | `Int32` little-endian (default `4`, min `3`) |
| `10..13` | `4` | `Argon2MemoryKiB` | `Int32` little-endian (default `262144` KiB = 256 MiB, min `65536` KiB in tests) |
| `14..29` | `16` | `Salt` | Random 16-byte salt from `Geralt.SecureRandom.Fill` (`Argon2id.SaltSize`) |
| `30..53` | `24` | `StreamHeader` | 24-byte header generated by `new IncrementalXChaCha20Poly1305(header, key, encryption: true)` |
| `54..N` | Variable | `Frames` | Sequence of framed ciphertext chunks: `[Int32 LE CiphertextLength (4B)][CiphertextBytes (PlaintextLen + 17B TagSize)]` |

- **Header Authentication (Associated Data)**: The 54-byte file header (`bytes 0..53`) is passed as `associatedData` on chunk `0` (and chunk `0` is always emitted, even for an empty input stream, with `ChunkFlag.Final`), binding the header parameters and version byte cryptographically to the keystream.
- **Chunk Framing & Final-Chunk Flag**: Input from `mongodump --archive --gzip` stdout is read into a 64 KiB buffer (`65,536` bytes) with one-chunk lookahead so the writer knows when EOF is reached. Non-terminal chunks are encrypted with `ChunkFlag.Message` (`0`); the terminal chunk is encrypted with `ChunkFlag.Final` (`3`).
- **Why Tampering, Reordering, Dropping, and Truncation Are Detected**:
  - `crypto_secretstream_xchacha20poly1305` maintains an internal 64-bit chunk counter in its state and increments it after every chunk; dropping or reordering any chunk desynchronizes the nonce and causes Poly1305 authentication to fail immediately.
  - Truncating the archive before the terminal chunk (or stripping the final chunk) means `ChunkFlag.Final` (`3`) is never observed before EOF, which the decryptor treats as an immediate authentication failure.

### 2. Two-Pass Restore Protocol

Because `mongorestore --archive --gzip` mutates the target database as bytes stream into its `stdin`, a single-pass decrypt-into-mongorestore pipeline could apply early collections/documents before encountering a corrupted or truncated chunk near the end of the file. To prevent partial restores:
1. **Pass 1 (Verify-Only)**: Opens the `.rrbak` file stream, validates the 54-byte header, derives the 32-byte key via `Argon2id.DeriveKey`, and decrypts every chunk through `IncrementalXChaCha20Poly1305.DecryptChunk` into a reusable 64 KiB stack/pooled scratch buffer (discarding the plaintext bytes), verifying that the final chunk carries `ChunkFlag.Final` and no trailing bytes exist after `ChunkFlag.Final`.
2. **Pass 2 (Apply)**: Only if Pass 1 completes with zero authentication or framing errors, seeks the `.rrbak` file stream back to byte `0` and streams the decrypted plaintext directly into `mongorestore --archive --gzip` `stdin`.

### 3. Mandatory Cryptographic & Streaming Verification Tests

`RoleRadar.Tests.Unit` and `RoleRadar.Tests.Integration` MUST include:
1. **Known-Answer / Deterministic Seed Vector Test**: Deterministic key + header round-trip verification.
2. **Wrong Passphrase Test**: Fails during Pass 1 on chunk `0` with authentication error.
3. **Flipped Bit Test**: Flipping any single bit in the 54-byte header, chunk length prefix, or ciphertext payload fails Pass 1 authentication.
4. **Truncated Stream Test**: Truncating the archive mid-chunk or after a `ChunkFlag.Message` chunk (missing `ChunkFlag.Final`) fails Pass 1 with a truncation/authentication error.
5. **Dropped Chunk Test**: Removing chunk `1` from a 3-chunk stream fails Pass 1 on the subsequent chunk due to internal nonce counter mismatch.
6. **Reordered Chunks Test**: Swapping chunk `0` and chunk `1` (or chunk `1` and chunk `2`) fails Pass 1 authentication.
7. **Corrupted Archive Restore Leaves Datastore Untouched Test**: In an integration test, corrupting the last chunk of a valid multi-chunk `.rrbak` archive causes `restore` to fail in Pass 1 before `mongorestore` is invoked, leaving the MongoDB collections completely untouched.
8. **Bounded-Memory Large Synthetic Stream Test**: Encrypting and decrypting a multi-megabyte synthetic stream processes chunk-by-chunk with constant buffer allocations (`<= 256 KiB` working buffers) without buffering the full archive in memory.
9. **Temp-Location Inspection Test**: Monitors the output directory and `%TEMP%` during backup and restore to prove zero plaintext temporary files are created.
