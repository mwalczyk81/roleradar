## How the gates ship

The spec says each story is shippable alone, and the owner may ship one pull request per gate, recreating `014-standards-first` from `main` after each merge. So:

- **Each gate ends mergeable**: build green with `-warnaserror`, fast tests and the gate's own checks green, lock files consistent, no half-finished mechanism left behind. A gate never leaves a deleted helper without its replacement.
- The `specs/014-standards-first/` folder and the one-line pointer in `specs/013-operability/spec.md` travel in the G1 pull request. After a merge, recreate the branch from `main`; `.specify/feature.json` is not tracked, so re-point it with `{ "feature_directory": "specs/014-standards-first" }`.
- ADR numbers are reserved by gate (0042 G1, 0044 G2, 0045 G3, 0046 G4a, 0047 G4b, 0043 G4c, 0048 G4d). Gaps between merges are fine; each pull request adds its own row to `docs/adr/README.md`.
- No gate depends on another. G2 and G3 both edit `web/app/lib/api-client.server.ts`; whichever merges second rebases onto the first. G1 and G2 both touch the Identity sign-in files in different places.
