# Identity Host Endpoints Contract

**Feature**: `005a-api-and-login` | **Date**: 2026-10-25

The identity host (`RoleRadar.Identity`) exposes standard OpenID Connect and OAuth 2.0 endpoints over HTTPS.

---

## 1. Discovery and Key Endpoints

### `GET /.well-known/openid-configuration`
- **Description**: Returns standard OpenID Connect provider configuration metadata.
- **Auth**: Anonymous
- **Response**: JSON document containing:
  - `issuer`: Fixed configured issuer URL (e.g. `https://localhost:5001`)
  - `jwks_uri`: URL of the JSON Web Key Set
  - `authorization_endpoint`: URL of `/connect/authorize`
  - `token_endpoint`: URL of `/connect/token`
  - `response_types_supported`: `["code"]`
  - `grant_types_supported`: `["authorization_code", "client_credentials", "refresh_token"]`
  - `code_challenge_methods_supported`: `["S256"]`
  - `id_token_signing_alg_values_supported`: `["RS256", "ES256"]`

### `GET /.well-known/jwks.json`
- **Description**: Returns active public JSON Web Keys for token signature verification.
- **Auth**: Anonymous
- **Response**: Standard JWKS JSON object containing `keys` array with `kty`, `use: "sig"`, `kid`, `alg`, and key modulus/exponent.

### `GET /health` and CLI `--healthcheck`
- **Auth**: Anonymous (internal loopback binding `http://127.0.0.1:8080/health`)
- **Self-Contained Probe**: Invoking `RoleRadar.Identity --healthcheck` requests this internal endpoint and exits with code 0 on healthy, 1 on failure.
- **Status**: 200 OK
- **Response**: `{"status": "Healthy"}`

## 2. Interactive Authentication Endpoints

### `GET /connect/authorize`
- **Description**: Initiates OpenID Connect authorization code flow with PKCE for confidential clients.
- **Parameters**:
  - `client_id` (string, required): Registered client ID (e.g. `roleradar-web`)
  - `redirect_uri` (string, required): Must exactly match registered redirect URI
  - `response_type` (string, required): Must equal `code`
  - `scope` (string, required): e.g. `openid profile roleradar.api offline_access`
  - `code_challenge` (string, required): SHA-256 hash of the PKCE code verifier
  - `code_challenge_method` (string, required): Must equal `S256`
  - `state` (string, required): CSRF mitigation token
- **Behavior**: If owner is not logged in, redirects to `/Account/Login`.

### `GET /Account/Login` & `POST /Account/Login`
- **Description**: Interactive owner login page.
- **Authentication**:
  1. Step 1: Prompt for owner username and password.
  2. Step 2: Prompt for 6-digit TOTP code generated by the owner's authenticator app.
- **Lockout**: Account locked for 15 minutes after 5 consecutive failed attempts.
- **Rate Limit**: Maximum 10 requests per minute per IP address.

---

## 3. Token Issuance Endpoints

### `POST /connect/token`
- **Description**: Issues access tokens, refresh tokens, and ID tokens.
- **Rate Limit**: Maximum 10 requests per minute per IP address.
- **Grant Types Supported**:

#### A. Authorization Code Grant (`grant_type=authorization_code`)
- **Parameters**: `client_id`, `client_secret`, `code`, `redirect_uri`, `code_verifier`.
- **Response**:
  ```json
  {
    "access_token": "<jwt-token>",
    "token_type": "Bearer",
    "expires_in": 600,
    "refresh_token": "<refresh-token>",
    "id_token": "<id-token>"
  }
  ```

#### B. Refresh Token Grant (`grant_type=refresh_token`)
- **Parameters**: `client_id`, `client_secret`, `refresh_token`.
- **Behavior**:
  - Validates and rotates the refresh token (one-time use).
  - If a previously consumed refresh token is presented, triggers reuse detection and invalidates the entire token family.
- **Response**: Returns a new 10-minute access token and a new rotating refresh token.

#### C. Client Credentials Grant (`grant_type=client_credentials`)
- **Parameters**: `client_id`, `client_secret`, `scope`.
- **Response**:
  ```json
  {
    "access_token": "<jwt-token>",
    "token_type": "Bearer",
    "expires_in": 300
  }
  ```
