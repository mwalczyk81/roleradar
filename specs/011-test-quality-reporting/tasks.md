# Tasks: Test Quality and Reporting

**Input**: Design documents from `/specs/011-test-quality-reporting/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/

**Tests**: Required and written first (constitution II, AGENTS.md). Each test task must be run and its failing output shown before the matching implementation task. Fictional data only. LF endings. No commit or push. Never run against the developer's running Mongo or stack. Every number written to research.md names the command or run that produced it. Pin every new tool, package and action from verified registry output, never from memory.

**Script test rule (applies to every new Unit test that launches `pwsh` or `git`)**: the Unit project also runs on the macOS and Windows jobs, so each such test builds its own fixture temp directory (and a temp git repo when git is needed), deletes it afterwards, sets an explicit process timeout (30 seconds default, process killed on expiry), uses no network and no dependence on this repo's git history, and skips with a stated reason if `pwsh` is not on PATH.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1 mutation, US2 reporting, US2b Allure, US3 property tests, US4 gate lint
- **STOP**: work halts for owner review.
- **AFTER PR VALIDATION RUN**: owned by the review step. It cannot start until the owner and Claude have opened the pull request and the nightly workflow's validation run has finished on it (the run is no-publish and has no secrets). The task text says what to read from the run. Nothing here is skipped silently: if the run did not happen, the task stays open and is reported as not run.
